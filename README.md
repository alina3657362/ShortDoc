# ShortDoc API

ShortDoc API — сервис для работы с PDF-документами.

Сервис умеет:
- регистрировать и авторизовывать пользователей;
- хранить пользователей и сессии в PostgreSQL;
- возвращать данные текущего авторизованного пользователя;
- обновлять ник пользователя и менять пароль;
- извлекать текст из PDF без авторизации;
- создавать сокращённую версию PDF без авторизации;
- сохранять оригинальный PDF, извлечённый текст и суммаризацию в историю авторизованного пользователя;
- возвращать историю документов пользователя;
- возвращать сохранённую суммаризацию конкретного документа;
- возвращать оригинальный документ из истории в виде текста;
- возвращать оригинальный документ из истории в виде PDF-файла;
- удалять сохранённые документы.

## Текущая логика

Сервис работает в двух режимах.

### Без авторизации

Пользователь может загрузить PDF и сразу получить результат:

- текст документа;
- сокращённую версию документа.

В этом режиме документ не сохраняется в историю.

### С авторизацией

Пользователь может загрузить PDF в историю. Сервер сразу:

1. проверяет access token;
2. определяет текущего пользователя;
3. извлекает текст из PDF;
4. отправляет текст в LLM;
5. получает сокращённую версию;
6. сохраняет оригинальный PDF в БД;
7. сохраняет извлечённый текст в БД;
8. сохраняет готовую суммаризацию в БД;
9. возвращает результат.

Отдельных статусов обработки и фоновых jobs сейчас нет. Запрос обрабатывается синхронно.

## Авторизация

Метод логина возвращает `access_token`.

Для авторизованных методов нужно передавать заголовок:

```http
Authorization: Bearer <access_token>
```

# Методы API

## Auth

### `POST /api/v1/auth/register`

Регистрирует нового пользователя.

Авторизация не требуется.

Поля запроса:
- `email` — почта пользователя;
- `nickname` — ник пользователя;
- `password` — пароль.

### `POST /api/v1/auth/login`

Авторизует пользователя по email и паролю.

Авторизация не требуется.

Поля запроса:
- `email` — почта пользователя;
- `password` — пароль.

Возвращает:
- `access_token`;
- `token_type`;
- данные пользователя.

### `GET /api/v1/auth/me`

Возвращает данные текущего авторизованного пользователя.

Авторизация требуется.

Метод определяет пользователя по access token из заголовка:

Возвращает:
- `id` пользователя;
- `email` пользователя;
- `nickname` пользователя;
- дату создания пользователя.

### `PATCH /api/v1/auth/me`

Обновляет данные текущего авторизованного пользователя.

Авторизация требуется.

Через этот метод можно:
- изменить ник пользователя;
- изменить пароль пользователя.

Почту через этот метод менять нельзя.

Для изменения ника достаточно передать поле `nickname`, для изменения пароля нужно передать текущий пароль и новый пароль, можно изменить ник и пароль одним запросом.

Возвращает обновлённые данные пользователя.

## Documents

### `POST /api/v1/documents/extract-text`

Извлекает текст из PDF-файла.

Авторизация не требуется.

Используется, когда нужно просто получить текст из документа без сохранения в историю.

Принимает:
- `file` — PDF-файл.

Возвращает:
- `filename`;
- `text`.

### `POST /api/v1/documents/summarize`

Создаёт сокращённую версию PDF-документа.

Авторизация не требуется.

Используется, когда пользователь хочет получить summary без сохранения документа в историю.

Внутри метода:
1. проверяется файл;
2. из PDF извлекается текст;
3. текст отправляется в LLM;
4. результат возвращается пользователю.

Принимает:
- `file` — PDF-файл.

Возвращает:
- `filename`;
- `summary`.

### `POST /api/v1/documents`

Загружает PDF-документ в историю авторизованного пользователя.

Авторизация требуется.

Внутри метода:
1. проверяется access token;
2. определяется текущий пользователь;
3. проверяется файл;
4. из PDF извлекается текст;
5. текст отправляется в LLM;
6. создаётся сокращённая версия;
7. документ сохраняется в историю пользователя;
8. суммаризация сохраняется для этого документа.

Принимает:
- `file` — PDF-файл.

Возвращает сохранённую суммаризацию документа.

### `GET /api/v1/documents`

Возвращает историю документов авторизованного пользователя.

Авторизация требуется.

Метод возвращает только документы текущего пользователя.

Возвращает:
- список документов пользователя.

### `GET /api/v1/documents/{document_id}/summary`

Возвращает сохранённую суммаризацию конкретного документа.

Авторизация требуется.

Метод проверяет, что документ принадлежит текущему пользователю. Если документ не найден или принадлежит другому пользователю, возвращается ошибка `404`.

Возвращает:
- id суммаризации;
- id документа;
- текст суммаризации;
- дату создания.

### `GET /api/v1/documents/{document_id}/text`

Возвращает оригинальный документ в виде строки.

Авторизация требуется.

Метод проверяет, что документ принадлежит текущему пользователю. Если документ не найден или принадлежит другому пользователю, возвращается ошибка `404`.

Возвращает:
- id документа;
- имя файла;
- извлечённый текст PDF.

### `GET /api/v1/documents/{document_id}/original`

Возвращает оригинальный PDF-файл из истории.

Авторизация требуется.

Метод проверяет, что документ принадлежит текущему пользователю. Если документ не найден или принадлежит другому пользователю, возвращается ошибка `404`.

Возвращает:
- PDF-файл с media type `application/pdf`.

### `DELETE /api/v1/documents/{document_id}`

Удаляет сохранённый документ авторизованного пользователя.

Авторизация требуется.

Метод удаляет:
- оригинальный PDF;
- извлечённый текст;
- связанную суммаризацию;
- запись документа из истории.

Если документ не найден или принадлежит другому пользователю, возвращается ошибка `404`.

| `POST /api/v1/documents/extract-text` | Нет | Извлекает текст из PDF без сохранения |
| `POST /api/v1/documents/summarize` | Нет | Возвращает summary PDF без сохранения |
| `POST /api/v1/documents` | Да | Создаёт summary и сохраняет PDF, текст и summary в историю |
| `GET /api/v1/documents` | Да | Возвращает историю документов пользователя |
| `GET /api/v1/documents/{document_id}/summary` | Да | Возвращает сохранённую summary документа |
| `GET /api/v1/documents/{document_id}/text` | Да | Возвращает оригинальный документ в виде строки |
| `GET /api/v1/documents/{document_id}/original` | Да | Возвращает оригинальный PDF-файл |
| `DELETE /api/v1/documents/{document_id}` | Да | Удаляет документ пользователя из истории |
