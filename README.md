# ShortDoc API

ShortDoc API — сервис для работы с PDF-документами.

Сервис позволяет:

- зарегистрировать пользователя;
- авторизоваться и получить access token;
- загрузить PDF в историю пользователя;
- получить список загруженных документов;
- извлечь текст из PDF без авторизации;
- получить сокращённый вид PDF без авторизации;
- получить summary сохранённого документа;
- удалить сохранённый документ.


## Авторизация

Для авторизованных методов используется токен, который возвращает метод логина.

Формат заголовка:

```http
Authorization: Bearer <access_token>
```

---

# Методы API

## Auth

### `POST /api/v1/auth/register`

Регистрирует нового пользователя.

Принимает:

- `email` — почта пользователя;
- `nickname` — ник пользователя;
- `password` — пароль.

Авторизация не требуется.

---

### `POST /api/v1/auth/login`

Авторизует пользователя по email и паролю.

Принимает:

- `email` — почта пользователя;
- `password` — пароль.

Возвращает `access_token`, который используется для доступа к истории документов.

Авторизация не требуется.

---

# Documents

## `POST /api/v1/documents/extract-text`

Извлекает текст из PDF-файла.

Метод нужен для быстрого получения текста документа без сохранения в историю.

Принимает:

- `file` — PDF-файл.

Возвращает:

- `filename` — имя файла;
- `text` — извлечённый текст.

Авторизация не требуется.

---

## `POST /api/v1/documents/summarize`

Создаёт сокращённый вид PDF-документа.

Метод работает без сохранения документа в историю. Он подходит для пользователей без аккаунта.

Принимает:

- `file` — PDF-файл.

Внутри метода:

1. Проверяется, что файл загружен.
2. Проверяется, что файл имеет расширение `.pdf`.
3. Из PDF извлекается текст.
4. Текст отправляется в LLM.
5. Возвращается сокращённый текст документа.

Возвращает:

- `filename` — имя файла;
- `summary` — сокращённый текст документа.

Авторизация не требуется.

---

## `POST /api/v1/documents`

Загружает PDF-документ в историю авторизованного пользователя.

Метод используется, когда пользователь хочет сохранить документ в своей истории.

Принимает:

- `file` — PDF-файл.

Внутри метода:

1. Проверяется авторизация пользователя.
2. Проверяется, что файл загружен.
3. Проверяется, что файл имеет расширение `.pdf`.
4. Файл сохраняется в хранилище.
5. Документ связывается с `user_id` текущего пользователя.
6. Создаётся задача обработки документа.

Возвращает:

- данные документа;
- данные задачи обработки.

Авторизация требуется.

---

## `GET /api/v1/documents`

Возвращает историю документов авторизованного пользователя.

Метод показывает только документы текущего пользователя.

Внутри метода:

1. Проверяется авторизация.
2. Из токена определяется текущий пользователь.
3. Возвращаются только документы, связанные с его `user_id`.

Возвращает:

- список документов пользователя.

Авторизация требуется.

---

## `GET /api/v1/documents/{document_id}/status`

Возвращает статус обработки сохранённого документа.

Метод нужен для сценария, когда документ обрабатывается не сразу.

Сейчас возможные поля статуса:

- `is_ready: false` — документ ещё обрабатывается;
- `is_ready: true` — документ готов;
- `error` — ошибка обработки, если она произошла.

Авторизация сейчас не обязательна, но для пользовательской истории этот метод лучше защищать авторизацией.

---

## `GET /api/v1/documents/{document_id}/summary`

Возвращает summary сохранённого документа.

Метод используется для получения результата обработки документа, который был загружен в историю.

Если summary ещё не готово, метод возвращает ошибку `SUMMARY_NOT_READY`.

Авторизация сейчас не обязательна, но для пользовательской истории этот метод лучше защищать авторизацией.

---

## `DELETE /api/v1/documents/{document_id}`

Удаляет сохранённый документ.

Метод удаляет:

- сам документ;
- связанную задачу обработки;
- связанное summary.

Авторизация сейчас не обязательна, но этот метод лучше обязательно защищать авторизацией, чтобы пользователь не мог удалить чужой документ.

---


# Логика работы сервиса

## Пользователь без аккаунта

Может использовать:

```text
POST /api/v1/documents/extract-text
POST /api/v1/documents/summarize
```

То есть пользователь может загрузить PDF, получить текст или сокращённый вид документа, но история документов не сохраняется.

## Авторизованный пользователь

Может использовать:

```text
POST /api/v1/documents
GET /api/v1/documents
```

То есть пользователь может загружать документы в историю и потом видеть список своих документов.

# Рекомендуемая модель доступа

| Метод | Авторизация |
|---|---|
| `POST /api/v1/auth/register` | не нужна |
| `POST /api/v1/auth/login` | не нужна |
| `POST /api/v1/documents/extract-text` | не нужна |
| `POST /api/v1/documents/summarize` | не нужна |
| `POST /api/v1/documents` | нужна |
| `GET /api/v1/documents` | нужна |
| `GET /api/v1/documents/{document_id}/status` | лучше нужна |
| `GET /api/v1/documents/{document_id}/summary` | лучше нужна |
| `DELETE /api/v1/documents/{document_id}` | лучше нужна |
| `POST /api/v1/documents/{document_id}/mock-ready` | только для разработки |
